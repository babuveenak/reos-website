# REOS Transformation Value Roadmap

## Scope and frozen decisions

This roadmap adds a business-value layer to the existing `/platform` route. It does not change the approved REOS brand, five-item navigation, seven Property Journey stages, twelve-stakeholder architecture, Ecosystem, Intelligence, Assistant, Platform, Trust Centre, evaluation, product maturity, or How REOS Works models.

The work answers one executive question: **why should an organization change the way it operates today?**

## Content guardrails

- No percentages, savings figures or ROI promises are used.
- REOS is positioned as **the connective operating layer**, not as a replacement for authorities or authoritative systems.
- “Operate” describes the organization’s adoption stage and explicitly uses the existing REOS execution model; it does not create a competing operating model.
- Product, trust, procurement, maturity and governance content remain in their approved sections.
- The twelve value lenses use buyer-friendly language and explicitly preserve the approved twelve-group stakeholder architecture.

## Acceptance criteria

- An executive can distinguish the present operating model from the REOS operating model without opening a product screen.
- Every requested stakeholder lens states current pain, desired outcome and how REOS helps.
- The page explains why traditional approaches break down without attacking a competitor or naming a specific product.
- The page retains one primary demo action and routes the secondary hero action to transformation context.
- The implementation introduces no new top-level navigation, governance model, maturity state or unsupported performance claim.
